# Grill Me: MILEAGE — лог интервью

**Задача:** MILEAGE (ДЗ.1) · **Дата:** 2026-10-05 · **Режим:** Grill Me (1.5.1)
**Опрошен:** заказчик (интервью, 6 вопросов) · **Статус:** все вопросы закрыты.

Правило: «пробег авто не больше 400 000 км — решение без изменений, иначе `review`».
Опрос вёлся по `docs/setup/code_map.md` и `docs/plan/plan_MILEAGE.md`.

## Не спрашивал — видно из кода и документов

- Пробег отсутствует / `null` → 422 на валидации, до решения не доходит
  (код: `backend/src/Domain/ApplicationValidator.php:43-46`).
- Место правила — `DecisionEngine`, после LTV-вердикта; порог из `rules.php`
  через конструктор, пробег — параметром `decide()` (код: `docs/setup/code_map.md:74-102`).
- Валидационная граница `vehicle.max_mileage_km = 500 000` остаётся и сосуществует
  с новым порогом решения (код: `backend/config/rules.php:23`).
- Механика сочетания с LTV: сначала LTV-вердикт, затем понижение
  (код: `docs/plan/plan_MILEAGE.md`, раздел «Допущения»).

## Вопросы и ответы

| # | Вопрос | Ответ заказчика |
|---|--------|-----------------|
| 1 | Граница 400 000: ровно 400 000 — ещё «не больше» (approve), review с 400 001? | **Да.** Триггер — строго `> 400 000`: 400 000 остаётся approve, 400 001 → review. |
| 2 | Правило понижает только approve → review или перекрывает любой вердикт? Ключевой случай: LTV-reject при пробеге 400 001. | **Только approve → review.** LTV-review остаётся review, LTV-reject остаётся reject — высокий пробег не смягчает решение. |
| 3 | Пустая строка mileage (`''`): сегодня нормализуется в 0 и валидна. Фиксировать как есть или требовать 422 (правка валидатора)? | **Фиксируем 0 как есть.** `ApplicationValidator` не трогаем; поведение закрепляется тестом. |
| 4 | Понижение молчаливое или помечать причину review в ответе API (`reason`)? | **Молчаливое.** Контракт ответа API не меняется, без `reason`. |
| 5 | Границы scope — как в `plan_MILEAGE.md` («Не входит»)? | **Да, как в плане.** Вне задачи: фронтенд, БД (schema/seed), LOAN-12 (`ltv_by_age`), изменение `max_mileage_km`, пороги/формула LTV, feature/HTTP-тесты, обновление `code_map.md`. |
| 6 | Переписать заодно формулировку LTV-границ в комментариях под код (`<=` в комментариях vs `<` в коде)? | **Не трогать формулировку.** В docblock `DecisionEngine` только добавляется описание правила пробега; расхождение комментариев LTV с кодом — отдельной задачей. |

## Итог — решения для intent_MILEAGE.md

1. Порог решения: понижение при `mileage > 400 000`; ровно 400 000 — без понижения (ответ в интервью).
2. Понижение только approve → review; review и reject не меняются (ответ в интервью).
3. Пробег отсутствует/`null` → 422 (код: `ApplicationValidator.php:43-46`); пустая строка → 0, текущее поведение фиксируется (ответ в интервью).
4. Понижение молчаливое, контракт ответа не меняется (ответ в интервью).
5. Scope по `plan_MILEAGE.md`, без расширений (ответ в интервью).
6. Формулировку LTV-границ в комментариях не переписываем (ответ в интервью).

Открытых вопросов нет.
