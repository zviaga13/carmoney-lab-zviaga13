# Intent MILEAGE: пробег авто не больше 400 000 км, иначе review

**Задача:** MILEAGE (ДЗ.1) · **Статус:** на утверждение заказчиком · **Дата:** 2026-10-05
**Источники:** интервью Grill Me (лог — `docs/intent/grill_MILEAGE.md`, 2026-10-05), код.

## 1. Замысел

Добавить в расчёт решения по заявке проверку пробега авто: если пробег не больше
400 000 км — решение без изменений; иначе — решение `review`.
Правило меняет вердикт валидной заявки, а не её валидность
(код: docs/setup/code_map.md:76).

## 2. Зачем

Сейчас решение зависит только от LTV, пробег на него не влияет
(код: docs/setup/code_map.md:111): заявка с любым пробегом получает approve,
если LTV даёт approve. Правило закрывает этот пробел: заявки с пробегом выше
порога уходят в review вместо автоматического approve.

## 3. Constraints

1. Порог — 400 000 км; «не больше» включает равенство: ровно 400 000 —
   без понижения, 400 001 — уже review (ответ в интервью, вопрос 1).
2. Правило понижает только approve → review; review остаётся review,
   reject остаётся reject — высокий пробег не смягчает решение
   (ответ в интервью, вопрос 2).
3. Пробег в заявке обязателен: отсутствует / null → заявка невалидна,
   решение не вычисляется (код: backend/src/Domain/ApplicationValidator.php:43-46).
4. Пустая строка пробега нормализуется в 0 и валидна — текущее поведение
   фиксируется без изменений (ответ в интервью, вопрос 3;
   код: backend/src/Domain/ApplicationValidator.php:43).
5. Валидационная граница 500 000 км остаётся и сосуществует с порогом решения:
   400 001–500 000 — валидная заявка (при LTV-approve будет review),
   больше 500 000 — отказ в обработке (код: backend/config/rules.php:23;
   ответ в интервью, вопрос 5).
6. Понижение молчаливое: контракт ответа не меняется, причина review
   не указывается (ответ в интервью, вопрос 4).
7. Пониженное решение review даёт `approved_limit = 0`, как и любое решение,
   отличное от approve (код: backend/src/Domain/AssessmentService.php:39).
